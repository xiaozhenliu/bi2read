# BiMyScribe Design Spec

生产 UI 的唯一实现来源为 `ui/**/*.slint`；归档目录中的 HTML 原型仅保留
设计决策历史，不作为行为、文案或布局规范。当前视觉层（色彩、圆角、控件尺寸、
状态语义着色）已并入本文档第 5–9 节；信息架构、滚动契约、窗口适配与验收标准也以
本文档为准。

状态：v1.3（redesign-v2 视觉层已实施）
更新：2026-08-16
适用范围：macOS 桌面端 Slint UI

## 1. 产品体验目标

BiMyScribe 是一个长时间运行、需要持续确认状态的桌面生产力工具。界面应像一个安静、可靠的任务工作台，而不是把所有实现细节铺满的监控面板。

设计关键词：**清晰、紧凑、稳定、可恢复**。

用户的主要路径只有四步：

1. 粘贴 B 站链接或 BV 号并创建任务。
2. 在队列中确认顺序与当前状态。
3. 查看所选任务的进度、失败原因或说话人信息。
4. 完成后打开 Markdown，失败后直接重试。

任何不直接服务于这四步的信息都属于次级信息，应通过分页、分组或渐进披露降低首屏噪音。

## 2. 设计依据

- [Apple HIG：Designing for macOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos/)：利用桌面空间减少嵌套层级，支持窗口缩放与键盘工作流。
- [Apple HIG：Split views](https://developer.apple.com/design/human-interface-guidelines/split-views)：使用主从分栏承载列表与详情。
- [Apple HIG：Scroll views](https://developer.apple.com/design/human-interface-guidelines/scroll-views)：避免同方向嵌套滚动，让可滚动范围显而易见。
- [Apple HIG：Toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars)：把全局创建动作放在顶部，把上下文动作放在详情附近。
- [Apple HIG：Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)：侧栏保持简洁，不在底部放置关键动作。
- [Slint `ListView`](https://docs.slint.dev/latest/docs/slint/reference/std-widgets/views/listview/)：长列表只实例化可见行。
- [Vercel Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines)：补充焦点、内容溢出、状态反馈和表单语义规则。

本规范借鉴成熟桌面应用的结构原则，不逐像素模仿任一产品。

## 3. 信息架构

### 3.1 主窗口

主窗口采用已确认的“专业三栏检查器”结构：

```text
┌────────────────────────────────────────────────────────────────────┐
│ 创建工具栏：链接输入 / 添加任务 / 设置                             │ 60
├───────────────┬───────────────────────────────┬────────────────────┤
│ 任务队列      │ 任务状态概览                  │ 说话人 / 任务信息  │
│ 数量 / 排序   │ 标题、状态、进度、关键操作    │ 可折叠检查器       │
│               │ 错误、警告、阶段历史          │                    │
│ 虚拟化列表    │ 唯一纵向滚动区                │ 唯一纵向滚动区     │
└───────────────┴───────────────────────────────┴────────────────────┘
      268                    自适应                    300 / 44
```

- 工具栏只承载全局动作。
- 左栏是任务队列，中栏专门负责所选任务的状态与阶段，右栏承载当前任务的说话人配置和只读信息。
- 中栏标题、进度和关键操作固定，不随阶段内容滚走。
- 说话人配置与任务状态概览彻底分栏，禁止在状态内容下方继续堆叠说话人表单。
- 右侧检查器默认打开“说话人”，可切换到只读的“任务信息”。
- 只有会修改任务行为的内容才使用“选项”或“设置”；纯展示内容不得命名为“任务选项”。
- 检查器可以整体收起为 44px 窄轨；收起后中栏自动扩展，窄轨保留明确的展开入口。
- 展开/收起不得提交、丢弃或重置说话人编辑内容。

### 3.2 设置

设置使用单一模态面板和左侧分类导航：

- 常规：工作目录、输出目录、保留策略、尚未开放的默认能力。
- 转写：FunASR 脚本与 Docker 运行要求。
- AI 润色：启用开关、连接、模型、地址、API 格式与安全提示。

设置页不得再使用一个包含所有类别的长表单。点击遮罩不丢弃草稿，只能通过“取消”或“保存”结束编辑。

## 4. 滚动契约

这是本 App 的强制规则：

1. 同一可见面板内最多存在一个纵向滚动容器。
2. 禁止在纵向 `ScrollView` 内再放纵向 `ScrollView` 或 `ListView`。
3. 队列、任务状态和右侧检查器是三个并列面板，可以各自独立滚动；它们不是嵌套滚动。
4. 错误文本、阶段列表等内容应自然展开，由中栏的唯一滚动容器负责。
5. 说话人检查器使用一个 `ListView`，不得在外层再包滚动容器。
6. 固定头部与滚动内容之间使用分隔线或轻微背景差，而不是额外卡片。
7. 超过 50 行或可能长期增长的集合必须使用虚拟化 `ListView`。
8. 横向滚动默认禁止；标题、状态和路径必须通过省略、换行或弹性布局处理。

## 5. 布局与尺寸

### 5.1 窗口

| Token | 值 | 说明 |
| --- | ---: | --- |
| `window-width` | 1180px | 默认宽度，容纳完整三栏 |
| `window-height` | 760px | 默认高度 |
| `window-min-width` | 920px | 检查器展开时仍保护中栏；更窄时建议收起检查器 |
| `window-min-height` | 600px | 保证摘要、关键操作和阶段内容同时可见 |
| `sidebar-width` | 268px | 默认队列宽度 |
| `sidebar-min-width` | 252px | 最小队列宽度 |
| `sidebar-max-width` | 292px | 最大队列宽度 |
| `inspector-width` | 300px | 展开的说话人检查器 |
| `inspector-collapsed-width` | 44px | 收起窄轨 |

### 5.2 控件与行高

| 元素 | 高度 |
| --- | ---: |
| 创建工具栏 | 60px；出现校验信息时 78px |
| 输入框（`AppTextField` 默认档） | 36px（`control-height-lg`）：创建工具栏与设置表单 |
| 输入框（`compact` 档） | 32px（`control-height`）+ 圆角 6：说话人行 |
| 创建工具栏主按钮 | 36px（`control-height-lg`） |
| 普通按钮 | 32px（`control-height`） |
| 紧凑按钮 | 28px |
| 任务行 | 68px |
| 检查器分页 | 32px |
| 阶段行 | 34px |
| 说话人行 | 60px（实现值；原规划 48px，为容纳「原始标签 · 出现 N 段」caption + 32px 输入两行内容按 4px 网格上调，见 `ui/components/job-detail.slint` `SpeakerRow`） |
| 设置标题栏 / 底部操作区 | 40px |

固定高度只用于单行控件和可预测行；多行错误与提示必须使用内容驱动高度。

### 5.3 间距

基础网格为 4px：`4 / 8 / 12 / 16 / 20 / 24 / 32`。

- 页面内边距：20–24px。
- 侧栏内边距：12–16px。
- 区块间距：16–20px。
- 同组控件：8–12px。
- 文本标签与输入框：4px。

### 5.4 圆角和边框

- 小控件：6px（`radius-sm`）。
- 按钮、输入、选中行和任务行：8px（`radius-md`）。
- 大型面板：12px（`radius-lg`），仅模态框和明确分组使用。
- 状态徽章（pill）：12px 全圆角（`pill-radius`），配合 24px 固定高度。
- 普通分区优先使用背景差或 1px 分隔线，不把每个区块都做成卡片。

## 6. 字体规范

使用系统 UI 字体。字号只允许以下语义级别：

| Token | 字号 / 字重 | 用途 |
| --- | --- | --- |
| `font-title` | 20px / 700 | 当前任务标题、设置标题 |
| `font-section` | 14px / 600 | 区块标题、重要状态 |
| `font-body` | 13px / 400 | 正文、输入、按钮、列表主文本 |
| `font-caption` | 12px / 400–600 | BV 号、耗时、辅助说明、字段标签 |

规则：

- 禁止 12px 以下的界面文字；9px 状态符号和 11px 标签均不允许。
- 相同组件内的按钮、输入和正文统一使用 `font-body`。
- 标题默认单行省略；错误和说明文本允许换行。
- 数字列保留稳定宽度，避免进度与耗时更新时造成布局跳动。
- 颜色不作为唯一状态信号，必须同时提供文字或符号。

## 7. 色彩与层级

视觉方向为低饱和的 macOS 工具型界面：

- `window-background`：应用底色。
- `sidebar-background`：比内容区略深，建立主从关系。
- `surface`：内容与输入表面。
- `surface-hover` / `surface-selected`：分别用于悬停和选中，不混用。
- `border` / `separator`：低对比分隔。
- `accent`：B 站品牌粉（`#FB7299`），只用于主按钮、进度和当前选中指示。
- `info`：B 站青，下载语义（元数据/下载音频/音频标准化阶段的点、进度条与徽章）。
- `polish`：紫色，AI 润色语义（可读文档/截图/最终文档/清理阶段的点、进度条与徽章）。
- `success` / `warning` / `danger`：只用于对应状态，配合文字标签。
- `info` / `polish` / `success` / `warning` / `danger` 各自配套 `-surface` / `-text`
  token（徽章底/文字）；`accent`（转写语义）复用 `surface-selected` 作底、
  `accent-text` 作文字，不单设 `accent-surface`。
  颜色不作为唯一信号——状态点与徽章必须同时输出文字标签（阶段名或状态名）。
- 错误和警告背景必须通过 Theme token 提供，不允许组件内硬编码颜色。

主按钮每个上下文最多一个。次要按钮采用中性边框与主文本色，不使用蓝色描边与蓝色文字争夺注意力。

## 8. 组件规范

### 8.1 创建工具栏

- 输入框占据剩余宽度，是工具栏主焦点。
- 空输入禁用“添加任务”；Return 与按钮执行相同动作。
- 错误在输入下方单行显示，编辑后可清除。
- “设置”是中性次要动作。

### 8.2 任务队列

- 标题行显示“任务队列”和数量。
- 上移 / 下移放在标题行，边界状态独立禁用。
- 任务列表使用 `ListView`。
- 每行只显示：标题、耗时、BV/P、当前阶段、总进度。
- 进度条和右侧百分比必须表达同一个“总进度”。
- 选中、悬停、键盘焦点、失败状态要可区分。
- 空状态不使用大面积空卡片，提供一句下一步指引。

### 8.3 任务详情

- 标题、BV/P、状态、耗时、总进度和关键操作固定在顶部。
- 运行中只显示“取消”；失败时主操作是“重试”；完成后主操作是“打开 Markdown”。
- “访达中显示”始终是次要操作。
- 中栏只包含错误/警告和阶段历史，使用一个 `ScrollView`。
- 说话人配置位于独立右侧检查器，使用一个 `ListView`；行结构为“原始标签 + 显示名称”，不重复展示同义字段。
- “任务信息”是检查器的第二页，只读展示创建/开始/结束时间、处理用时、视频时长、媒体占用、Markdown 字数、保留策略和截图产物状态。
- 时间使用本地时区；缺失值显示“—”，尚未产生的文件统计显示“尚未生成”。
- 媒体占用读取当前保留的 `source.audio` / `source.video` 实际大小；文件被清理后显示“已按保留策略清理”，不伪造为 0 B。
- Markdown 字数优先统计最终 `full.md` 的非空白字符数；最终文档不存在时回退到原始稿并明确标记“原始稿”。
- 检查器提供“收起”按钮；收起后显示 44px 窄轨、当前分页名称和“展开”按钮。
- 无数据时显示明确空状态，不渲染空分组。

#### 8.3.1 任务信息数据契约

右侧“任务信息”页由 `JobDetailData` 的单一快照驱动。Rust 控制器在
选中任务、任务状态快照更新或说话人保存后重新计算需要的字段；Slint
只负责展示，不从队列行或文件名推断状态。

| 字段 | 唯一来源与格式 | 缺失/刷新语义 |
| --- | --- | --- |
| 标题、BVID、分 P、状态、总进度 | `Job` 与 `JobViewSnapshot`；状态使用 `JobStatus::label()`，进度 0–100 | 每次任务快照一起替换 |
| 创建/开始/结束时间 | `Job.created_at`、`started_at`、`finished_at`；本地时区 `YYYY-MM-DD HH:mm:ss` | 未记录显示“—” |
| 处理用时 | `finished_at - started_at`；运行中使用当前时间差 | 未开始显示“—”，不能把 `00:00` 当作已处理 |
| 视频时长 | 仅读取 `Job.duration_ms` | 元数据未完成或零值显示“—” |
| 媒体占用 | 当前存在的 `work_dir/source.audio` 与 `source.video` 文件大小之和 | 无文件且已按保留策略清理显示“已按保留策略清理”；其他情况显示“尚未生成” |
| Markdown 字数 | 优先读取最终 `full.md`；否则读取 `transcript.raw.md`；统计非空白字符 | 回退值追加“（原始稿）”；文件尚未产生显示“尚未生成” |
| 保留策略、截图产物 | `Job.retention` 与当前截图能力 | 截图后端尚未开放时固定显示“未启用” |

所有字段在切换任务时同时更新；没有数据时使用上述占位文本，不渲染
`0 B`、`00:00` 或空字符串来暗示不存在的产物。字数统计是非空白字符
计数，并不宣称自然语言分词结果。文件大小与 Markdown 计数在 UI 线程
读取当前快照对应的目录；若实测大文档造成可感知阻塞，应改为后台快照
缓存（记录为独立性能问题，不改变后端流水线契约）。

### 8.4 设置

- 左侧分类是单选导航，当前页有明显选中背景与 3px 强调条。
- 字段标签直接作为输入控件的 accessible label。
- LLM 未启用时隐藏连接字段，仅保留解释和启用开关。
- 远程端点警告靠近 Base URL。
- 截图功能在实现前保持禁用并明确标记“暂不可用”。
- 点击遮罩不关闭；“取消”丢弃草稿，“保存”提交草稿。

## 9. 交互状态与可访问性

- 所有自定义点击元素必须具有正确 role、label、enabled 和 default action。
- 所有按钮支持 Space / Return，并提供可见键盘焦点。
- 检查器分页按钮使用 `tab-list` / `tab` / `tab-panel` 语义，并暴露选中状态。
- 检查器展开/收起按钮暴露明确 label，支持 Space / Return；收起后焦点可到达展开按钮。
- 进度条使用 `progress-indicator`，暴露 0–100 数值或“处理中”。
- 列表行支持键盘聚焦与激活。
- 表单输入必须有可读标签；错误和保存结果后续应使用 live region 通知。
- 持续动画应尊重“减少动态效果”；Slint 尚未桥接系统偏好前，动画只能用于真实的不确定进度，不能做装饰。
- 不依赖颜色表达完成、运行、失败或禁用。

## 10. 窗口适配

- `>= 1080px`：显示完整三栏，队列 252–292px，检查器 300px，状态概览占剩余空间。
- `920–1079px`：默认收起检查器为 44px 窄轨，中栏占据释放的空间。
- 接近最小宽度时：收起检查器并收紧页面边距，不缩小字体。
- 低于最小尺寸不支持，避免通过压缩字号或制造横向滚动勉强适配。
- 详情标题和路径必须处理极长文本；操作按钮不得覆盖标题或元数据。
- 后续若支持更窄窗口，应折叠侧栏，而不是让双栏继续挤压。

## 11. 验收标准

1. 主窗口中不存在同方向嵌套滚动。
2. 默认窗口下，摘要、关键操作和检查器分页始终可见。
3. 失败 fixture 的完整错误可通过详情页唯一滚动区访问。
4. 10 个阶段不会出现独立滚动条。
5. 10 个说话人仅使用一个列表滚动条，并且不位于任务状态内容下方。
6. 设置按 3 类展示，默认尺寸下不依赖长表单滚动。
7. 界面无 12px 以下文字；按钮、输入和正文基线一致。
8. 队列使用虚拟化列表，横向滚动始终关闭。
9. 920×600（检查器收起）与 1180×760（检查器展开）下无裁切、重叠或横向滚动。
10. 检查器展开/收起不修改说话人、任务或设置草稿。
11. “任务信息”不出现输入、开关或其他可编辑控件；所有数值来自任务状态或实际产物。
12. `cargo check`、`cargo test`、`cargo clippy --all-targets -- -D warnings` 通过。

## 12. 暂不纳入本轮

- 原生文件选择器。
- 系统深色模式与系统“减少动态效果”桥接。
- 可拖拽侧栏分隔线；本轮只实现右侧检查器的显式折叠。
- 完整菜单栏快捷键与全局状态通知。

这些能力应延续本规范的层级、Token 与滚动契约，不得重新引入长表单或同方向嵌套滚动。
