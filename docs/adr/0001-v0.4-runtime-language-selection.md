# ADR-0001：v0.4.0 Runtime 与语言选择契约

状态：Accepted（已实施于 v0.4.0）
日期：2026-08-18
目标版本：v0.4.0
产品依据：[PRD 7.4](../product-requirements.md#74-v040-用户需求说明可信的中英文转写)
交互依据：[v0.4.0 Design Plan（归档）](../archive/v0.4.0-runtime-language-selection.md)

## 背景

作出本决策时，v0.3.0 的 GUI 和 CLI 在创建任务时只把视频身份与保留策略写入 `Job`。Pipeline
在执行转写阶段才从可变的全局 `Config` 解析 Runtime，且 Runtime contract v1 没有源语言输入。
结果是：任务创建后修改设置可能改变其执行身份，英文视频也可能进入中文模型而仍产出文件。

v0.4.0 不建设 Runtime 能力发现或兼容性认证。用户或 Agent 查看 Runtime 的说明后自行选择，
BiMyScribe 只保证选择被持久化、传递、报告且不被静默改变。

## 决策

### 1. `Job` 拥有冻结的转写选择

在 `jobs` 模块定义并持久化两个值对象：

```text
SourceLanguage = auto | zh | en

TranscriptionSelection
├── runtime_source       bundled | external
├── runtime_project      创建时解析并规范化的绝对路径
├── runtime_data_dir     创建时使用的绝对路径
├── runtime_identity     Runtime manifest + 内容 fingerprint 的稳定身份
├── runtime_backend      native-uv | docker-compose
├── model_description    可空，仅供说明
├── requested_language   SourceLanguage
└── created_from         app | cli
```

`TranscriptionSelection` 是任务恢复、重试、GUI/CLI 展示和 Evidence 元数据的唯一来源。全局
`Config` 只提供新任务默认值；任务创建完成后，设置变化不影响已有任务。

旧任务缺少该字段时统一标记 `legacy-unrecorded`，不使用加载时 effective Runtime 自动补值，
也不伪造历史 Runtime 或语言。已完成任务仍可阅读既有 Evidence；未完成任务继续转写或旧任务
重试前，必须通过 App 的“使用新设置重建任务”显式选择，CLI 则返回需要重建的稳定错误。

### 2. `funasr` 保持唯一 Runtime seam

不新增 Runtime registry 或只转发调用的语言路由模块。`funasr` 模块加深现有 interface：

```text
describe_runtime(project, data, source) -> RuntimeDescription
run(TranscribeRequest { selection, ... }) -> TranscribeOutcome
```

`describe_runtime` 负责 manifest 解析、路径规范化、fingerprint、ready record 匹配和可选说明字段；
调用者不重复读取 manifest。说明字段缺失合法，返回“未提供”，不推断兼容性。

`run` 只接受冻结的 `TranscriptionSelection`，不再接受可变 `Config` 中的 Runtime 路径。它负责：

- 向 native-uv 和 Docker adapters 传递同一个 `--language auto|zh|en`；
- 校验 Runtime identity 与 ready record 未在任务创建后改变；
- 拒绝空 segments、未知 schema 和无效时间范围；
- 返回 utterances 以及 Runtime 实际报告的语言、模型或身份；未报告保持 `None`。

### 3. Runtime contract v2 只定义执行语义，不声明能力

contract v2 的强制变化只有：

- 转写入口接受 `--language auto|zh|en`；
- normalized 输出可回报 `reported_language`、`model` 和 `runtime_identity`；
- 空 segments 是失败，不能作为成功输出。

manifest 可选提供 `display_name`、`model_description`、`recommended_languages`、
`auto_detection` 和 `known_limitations`，仅用于展示。BiMyScribe 不验证这些说明，不据此隐藏
CLI 参数，也不把它们当作兼容性保证。

contract v1 继续可被读取和展示，但不具备 v2 的语言传递契约。用户可查看其限制；新建
v0.4.0 及后续任务若选择 v1 Runtime，创建阶段明确拒绝并提示更换或升级，不静默使用旧默认模型。

### 4. Evidence 与任务状态分离

`transcript.raw.json` 继续只保存 `Vec<Utterance>`，避免破坏现有文档重建接口。处理身份写入
`Job.transcription_selection`，运行结果写入：

```text
TranscriptionResult
├── reported_language: Option<SourceLanguage>
├── reported_model: Option<String>
└── reported_runtime_identity: Option<String>
```

两者随 `state.json` 原子持久化，并进入最终 Markdown 元数据与 GUI/CLI 结果。Runtime 未报告的
字段显示“未报告”，不能用请求值冒充实际值。

### 5. GUI 与 CLI 共享任务创建 interface

在 `jobs` 或现有 controller 层提供一个任务构造入口，接收视频身份、
`TranscriptionSelection` 和保留策略，完成默认阶段初始化。GUI 和 CLI 不各自复制冻结规则。

GUI 负责确认模态框和显示错误；CLI 负责参数解析。两者都先调用 `describe_runtime`，再通过同一
任务构造入口持久化选择。CLI 省略 `--language` 时传入 `auto`。

### 6. CLI JSON 是版本化 interface

CLI 定义统一 envelope：

```text
CliEnvelope<T>
├── schema_version: 1
├── ok: bool
├── data: T | null
└── error: { code, message, action? } | null
```

`runtime status --json` 和 `transcribe --json` 的 stdout 恰好输出一个 envelope；进度与诊断写入
stderr。参数错误、Runtime 未就绪、Pipeline 失败均返回稳定错误码与非零退出码，JSON 模式不
进入交互提示。

## 模块职责

| 模块 | v0.4.0 interface | 隐藏的 implementation |
| --- | --- | --- |
| `jobs` | `SourceLanguage`、`TranscriptionSelection`、任务构造与迁移 | serde 默认、旧任务兼容、冻结不变量 |
| `funasr` | `describe_runtime`、`run(TranscribeRequest)` | manifest v1/v2、fingerprint、backend argv/env、normalized 解析 |
| `pipeline` | 消费 `Job` 的冻结选择 | 阶段恢复、结果持久化、空 Evidence 拒绝 |
| `desktop` / `ui_bridge` | 创建输入与只读展示 | Slint model 映射、确认状态、错误文案 |
| `cli` | 参数与 `CliEnvelope` | clap、stdout/stderr、退出码映射 |

测试只跨上述 interface 观察行为，不为 manifest parser、语言 argv builder 或 JSON formatter 新建
公开 seam。native-uv 与 Docker 是 `funasr` seam 下已有的两个 adapters。

## 不变量

- 用户或 Agent 的 Runtime、语言选择在任务创建后不可变。
- Pipeline 不从当前 `Config` 重新解析已有任务的 Runtime。
- App 与 CLI 使用同一种 `SourceLanguage`、`TranscriptionSelection` 和迁移规则。
- `auto` 是显式请求值；失败时不回退为 `zh` 或 `en`。
- Runtime 说明不是能力声明或兼容性认证。
- 请求身份、Runtime 回报和缺失状态分别记录，不相互冒充。
- 未知 schema、空 segments、无效时间范围或 identity 改变均不能完成转写阶段。
- `transcript.raw.*` 仍是不可覆盖的 ASR Evidence；LLM 不参与语言选择或错误回退。

## 迁移与兼容

1. 新字段全部使用 serde 向后兼容默认，旧队列可以加载并标记 `legacy-unrecorded`。
2. 缺少 selection 的旧任务不从当前 Config 补值；已有 Evidence 继续可读，继续转写必须重建。
3. Runtime contract v1 可查询但不能创建带语言选择的新任务。
4. CLI JSON 新 schema 只在 `--json` 下生效；人类可读默认输出保持最终文档路径。
5. 发布前必须验证旧 `queue.json`、旧 `state.json` 和 v1 Runtime 的明确失败行为。

## 验证策略

- 纯 Rust fixture 覆盖值对象解析、serde 迁移、任务冻结、manifest v1/v2 和 identity 变化。
- fake Runtime 项目覆盖 native-uv/Docker 命令构造、三种语言传递、normalized 结果与空结果拒绝；
  不创建 Python/uv 环境。
- CLI 进程测试覆盖 stdout 单对象、stderr 进度、退出码和稳定错误码。
- UI fixture 覆盖 Runtime 可用、未就绪、说明缺失、三种语言、取消与两档窗口尺寸。
- 真实 Docker 固定中英文样本由质量 issue 执行；native-uv 只消费获批干净环境的既有证据。

## 被否决方案

- **Runtime 主动声明并由 App 验证能力**：实现和维护成本过高，也与用户自行判断的产品决策冲突。
- **Pipeline 每次读取当前 Config**：破坏任务冻结、恢复与可追溯性。
- **GUI 与 CLI 分别构造任务快照**：冻结和迁移逻辑会漂移。
- **新增 Runtime registry**：当前只有 bundled 与单个 external 路径，没有第二个真实注册来源。
- **把处理身份嵌入 raw transcript 数组**：会破坏现有 Evidence 读取 interface。
