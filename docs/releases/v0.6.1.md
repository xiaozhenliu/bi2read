# bi2read v0.6.1

本版本是 v0.6.0 版本线上的兼容性修复发布：产品更名为 bi2read，统一界面视觉，并修复音频
流水线、Runtime 内存耗尽与超时、Runtime 更换后的重试、详情面板实时状态和 CLI 结构化输出
等问题。智能文字处理、数据格式与 Runtime 契约与 v0.6.0 相同。

## 主要变化

- **产品更名为 bi2read**：App、命令行、bundle 标识（`com.xiaozhenliu.bi2read`）和公开仓库
  （`xiaozhenliu/bi2read`）统一使用新名称。首次启动时，如果只有旧的
  `~/Library/Application Support/BiMyScribe` 状态目录，会一次性原子迁移到
  `~/Library/Application Support/bi2read`，并把位于旧目录内的默认工作目录改指向新位置；
  用户自选路径和 `~/Documents/BiMyScribe` 下已有的文稿不移动。
- **视觉统一**：B 站蓝语义配色、白色输入框、18/14/12px 字号层级、队列信息分层、
  内容自适应行高，说话人列表只保留一条收尾线。
- **音频流水线恢复**：从 Finder 启动时也会在 `~/.local/bin`、Homebrew 和 MacPorts 的标准目录
  查找 FFmpeg/ffprobe，找不到时给出明确提示；下载的音频原子写入并拒绝被截断的响应；多分 P
  视频使用所选分 P 的时长。
- **Runtime 内存耗尽与超时**：转写失败区分“Runtime 内存不足”（`runtime-out-of-memory`）与
  “Runtime 超时”（`runtime-timeout`）；Docker 后端每 5 秒探测引擎，连续失联后停止等待，不再
  永久停在运行中；每次转写把退出码、OOM 标记与分类写入任务目录的 `logs/runtime-exit.json`。
  App 重启时被中断的转写阶段标记为失败并提供重试，不再自动重放，避免再次耗尽内存。
- **Runtime 更换后的重试**：任务冻结的 Runtime identity 与当前 Runtime 不一致时，任务进入
  “等待用户操作”并提供重建入口，可用当前 Runtime 重新创建任务，不再反复重试失败。
- **详情面板实时同步**：运行中的任务详情标题与阶段时间线随实时推送更新阶段和进度，
  不再停在“排队中”。
- **CLI 结构化输出**：`transcribe --json` 的标准输出只包含 JSON 结果，不再混入 ffprobe 或
  `docker rm` 的输出；ffprobe 检查记录追加到 `logs/ffmpeg.log`。
- **Runtime 兼容**：App 优先读取 `bi2read-runtime.toml`，继续兼容旧 `bimyscribe-runtime.toml`；
  内置原生 Runtime 同时收到新旧两个 Runtime identity 环境变量，v2.0.0 仍会在结果中回报实际
  处理身份；打包自检同时接受两种 manifest 文件名。

## 兼容性与升级

- 从 v0.6.0 升级无需手动迁移：设置、队列、任务、Evidence 与 `content-current.v1.json` 均保持
  原格式，状态目录在首次启动时自动迁移。迁移后请勿再运行旧的 BiMyScribe App，以免重新创建
  旧状态目录；旧 App 可在确认新版本正常后删除。
- 由于 bundle 标识改变，macOS 会把 bi2read 视为新 App，首次启动可能再次询问文件或网络权限。
- Runtime 固定输入保持 FunASR v2.0.0（contract 2），uv 保持 0.11.23。
- 仅支持 Apple Silicon macOS 13 或更高版本。

## 安装

本 Release 不提供官方签名并经 Apple 公证的 DMG。Apple Silicon Mac 可从源码运行
`scripts/build-macos-local.sh`，直接回车使用适合本机自用的 ad-hoc 签名。
FFmpeg 仍需单独安装。

## 已知限制

- 固定的原生 Runtime v2.0.0 的英文结果仍按 VAD 段输出，可能缺少句末标点；英文按句分段与
  估算时间戳需要后续 Runtime 版本。
- Docker 后端的模型集合占用较多内存；若出现“Runtime 内存不足”，请为 Docker Desktop 分配
  更多内存，或改为明确选择中文/英文后重试。
- 尚不提供官方签名、公证的 DMG；界面固定为浅色。
- FFmpeg 需要单独安装；ASR 首次安装需要下载模型。
- 图文精读、关键帧提取与图片内容包属于后续 v0.7.0 规划阶段。

## English

This is a compatibility release on the v0.6.0 line: the product is renamed to bi2read, the interface is
visually unified, and fixes cover the audio pipeline, Runtime out-of-memory and timeout handling, retry after a
Runtime change, live detail-pane status, and CLI structured output. Smart text features, data formats, and the
Runtime contract are unchanged from v0.6.0.

### Highlights

- **Renamed to bi2read**: the app, CLI, bundle identifier (`com.xiaozhenliu.bi2read`), and public repository
  (`xiaozhenliu/bi2read`) use the new name. On first launch, a lone legacy
  `~/Library/Application Support/BiMyScribe` state directory is moved atomically to
  `~/Library/Application Support/bi2read`, and defaults that pointed inside it follow the move. User-selected
  paths and existing documents under `~/Documents/BiMyScribe` are not moved.
- **Unified visuals**: Bilibili-blue semantic colours, white input fields, an 18/14/12px type scale, layered
  queue information, content-sized rows, and a single closing rule under the speaker list.
- **Audio pipeline recovery**: Finder-launched apps also look for FFmpeg/ffprobe in the standard
  `~/.local/bin`, Homebrew, and MacPorts locations and report a clear error when they are missing; downloaded
  audio is published atomically and truncated responses are rejected; multi-part videos use the selected
  part's duration.
- **Runtime out-of-memory and timeout**: failures distinguish `runtime-out-of-memory` from `runtime-timeout`;
  the Docker backend probes the engine every 5 seconds and stops waiting after repeated misses instead of
  staying "running" forever; every transcription writes its exit code, OOM flag, and classification to
  `logs/runtime-exit.json` in the job directory. A transcription interrupted by an app restart is marked
  failed with a retry action instead of being replayed automatically.
- **Retry after a Runtime change**: when a job's frozen Runtime identity no longer matches the current
  Runtime, the job moves to "needs user action" with a rebuild action instead of failing on every retry.
- **Live detail pane**: the detail header and stage timeline of a running job follow live stage and progress
  updates instead of reading "queued" until the job finishes.
- **CLI structured output**: `transcribe --json` prints only the JSON result on stdout; ffprobe and
  `docker rm` output no longer leaks into it, and the ffprobe check is appended to `logs/ffmpeg.log`.
- **Runtime compatibility**: the app reads `bi2read-runtime.toml` first and still accepts the legacy
  `bimyscribe-runtime.toml`; the bundled native Runtime receives both the new and the legacy identity
  variable so v2.0.0 keeps reporting the identity that processed the job; the package self-check accepts
  both manifest names.

### Compatibility and upgrades

Upgrades from v0.6.0 need no manual migration. Settings, queue entries, jobs, Evidence, and
`content-current.v1.json` keep their formats, and the state directory moves on first launch. Do not run the old
BiMyScribe app after migrating, or it recreates its old state directory; remove it once bi2read works. Because
the bundle identifier changed, macOS treats bi2read as a new app and may ask for file or network permissions
again. Runtime inputs remain FunASR v2.0.0 (contract 2) and uv 0.11.23. macOS 13 or newer on Apple Silicon is
supported.

### Installation

This release does not provide an officially signed and notarized DMG. On Apple Silicon macOS, run
`scripts/build-macos-local.sh`; press Enter for ad-hoc signing suitable for the machine that built it.
FFmpeg must be installed separately.

### Known limitations

English output from the pinned native Runtime v2.0.0 still follows VAD segments and may lack sentence
punctuation; sentence-level English segmentation with estimated timestamps needs a later Runtime release. The
Docker model set needs a lot of memory; if a job reports that the Runtime ran out of memory, give Docker Desktop
more memory or retry with an explicit Chinese/English language.
No officially signed and notarized DMG or dark mode is provided. FFmpeg is external, and first-time ASR setup
downloads models. Illustrated content packages and keyframes are scheduled for v0.7.0.
