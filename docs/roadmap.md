## 文档定位

本路线图说明 BiMyScribe 从当前产品走向可信视频消费工具的阶段路径，只回答四个问题：

1. 当前已经可靠交付什么；
2. 距离下一阶段还缺什么；
3. 各阶段按什么顺序推进；
4. 用什么结果判断一个阶段已经完成。

长期产品行为与验收口径由 PRD 的需求 ID 定义，用户流程与界面进入设计规范，模块契约进入
架构或 ADR，样本、实验过程和实施证据进入对应 issue，已发布事实进入版本化 Release Notes。
其他文档不得复制本文件的交付状态和优先级。

状态词只有以下四种：

- **已交付**：实现、验证、错误行为和用户说明均有证据；
- **当前**：正在跨越的最高优先级产品门槛；
- **候选**：方向已经明确，但必须等待前一阶段证据或排期裁决；
- **阻塞**：缺少明确输入、授权或外部证据，不能安全推进。

## 产品战略与交付阶段

BiMyScribe 当前只有一个产品战略目标：**让用户可信、可核对地快速消费长视频**。
它要求用户先得到保留来源的文字结果，再逐步获得更高密度的理解和图文内容；这不是把正文、
摘要和图文列成三个并行方向，而是同一消费目标的两个交付阶段。

- **v0.5.0 可信文字消费**：把 Evidence 变成可读、可核对的文字消费闭环，包含忠实正文、
  章节、一个默认摘要和重点。
- **v0.6.0 图文精读**：在文字闭环稳定后，增加用户明确选择的视频下载、关键帧/幻灯片和
  可移动内容包，并把视觉资产与文字来源对齐。

Evidence、Structure、Interpretation、Presentation 仍是不同的内容层和可信度边界；版本
阶段只描述交付顺序，不合并这些层，也不把多语言、多平台、插件或内容库列为当前并行战略。
任何下游增强失败都不能覆盖或隐藏 Evidence。

## 当前基线

v0.5.0 已可靠交付以下基础：

- **输入与执行**：Bilibili URL、BV、AV、短链、多分 P、持久队列、取消、重试和恢复；
- **本地 Evidence**：FFmpeg 标准化、FunASR Runtime、带时间戳和说话人的原始 JSON 与
  Markdown；
- **派生文档**：确定性合并相邻说话人片段、可选本地 LLM 整理、失败回退和最终 `full.md`；
- **产品入口**：macOS Slint 桌面界面，以及共享同一生产流水线的 CLI；
- **Runtime**：bundled/external 解析，以及 native-uv、Docker Compose backend；v0.4.0 已交付
  Runtime 来源、模型、语言选择和实际处理身份的透明度；
- **历史管理**：v0.4.1 已交付终态任务删除、清空历史和重启后的持久删除语义；
- **可信文字消费**：v0.5.0 已交付忠实正文、章节、默认摘要、重点、来源核对、受限状态和
  内存单项重生成；原始 Evidence 始终可访问；
- **交付与治理**：版本化 Release Notes、公开快照过滤、顺序化发布门禁和分阶段设计流程。

这些事实证明产品流水线、回退接口和 Runtime 选择透明度存在，但不证明真实视频的识别质量
对所有领域都满足稳定阅读要求；用户仍需核对来源状态和原始 Evidence。

## 最近完成：v0.4.0–v0.5.0

v0.4.0 的固定英文样本起始基线已经完成，并证明旧 Runtime 曾用中文 ASR 模型处理英文音频。当前
Runtime v2 按既定方案使用中文/英文 Paraformer profile，SenseVoiceSmall 只负责 auto 检测；
英文 Docker/App 回归已按该既定 profile 完成，中文只完成契约、结构和失败行为验证，不设置正确率
benchmark。

本阶段的完成定义：

1. 用户能查看每个 Runtime 的来源、模型、建议语言和已知限制，并自行选择；产品不认证其
   兼容性，也不静默代替用户切换；
2. 既有英文视频能用明确选择的 Runtime 和语言完整跑通 Docker/App 生产路径；中文主路径
   通过 contract、结构、时间/speaker 字段和失败行为验证；
3. 英文 speaker 归属、时间映射、原始 Evidence 和失败行为可与既有 raw transcript 参考核对；
4. 既有英文 raw transcript 只作为回归参考；本版本不伪造人工 gold 的 WER/CER，也不把中文
   正确率 benchmark 作为门槛；
5. UI、CLI 和用户文档能显示 Runtime 说明、用户选择和实际处理身份；CLI 提供稳定 JSON，
   不发生交互式阻塞或静默回退；
6. 短视频、混合语言和低置信度回退按实际能力标记，但不作为本阶段的阻塞边界案例。

起始基线不得自动重复执行。样本标识、哈希、耗时、指标明细和后续方案的比较结果由对应
issue 保存，本文件只在证据改变阶段状态、优先级或完成判断时更新。

v0.4.1 已完成终态任务删除和历史清空：删除会同步移除任务记录、工作目录和专属输出，
重启不再复现；排队或运行中的任务必须先取消。该版本没有改变 Runtime 或 Evidence 契约。

v0.5.0 已完成可信文字消费闭环，并通过 Rust、Docker FunASR 真实链路、真实窗口验收、独立审核、
private/public/runtime/approve 门禁和 source-only published 匿名闭环。

## 维护规则

- 新证据改变优先级、阶段门槛或完成状态时，只更新本文件；PRD 不保存开发快照；
- 每个“当前”或“候选”项进入实施前必须有独立 issue，记录输入、范围、checklist 和证据；
- 路线图只保留足以解释决策的证据结论，不保存样本哈希、逐次实验数据或实现过程；
- 版本发布后，把用户可见事实写入对应 Release Notes，不把本文件复制成日期进度报告；
- 无法从源码、测试、产物或人工验收证明的结论标为阻塞或未知，不以代码入口存在代替交付
  证据。
